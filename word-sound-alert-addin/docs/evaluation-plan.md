# 評価計画(案)

## 目的

視覚的な下線に代えて、あるいは加えて、効果音と読み上げで誤りを通知することが、
誤りへの気づきやすさ、修正までの時間、作業負荷、主観的な使いやすさにどう影響するかを明らかにする。

## 参加者

- 視覚障害のある学生(全盲、弱視)およびスクリーンリーダー利用者。
- 対照として晴眼の学生。
- 目安は各群 8 名から 12 名。事前に Word とスクリーンリーダーの利用経験を聞き取る。

## 実験計画

参加者内計画(各参加者がすべての条件を体験)とし、順序効果を避けるためラテン方格で条件の順序を割り付ける。

条件の例

- 条件 A(通知なし): 効果音と読み上げをオフ。Word 標準の下線のみ(スクリーンリーダー利用者は通常の校正機能のみ)。
- 条件 B(効果音のみ): 種別で異なるイヤコン。読み上げなし。
- 条件 C(効果音と読み上げ): イヤコンに加えて種別と語を読み上げ。
- 条件 D(単一音): 種別を区別しない 1 種類の音(音の区別の効果を見る場合)。

条件はタスクペインの「評価用ログ」パネルで条件名を入力して記録する。
設定の切り替えは「設定」パネルで行う(効果音のオン/オフ、プリセット、読み上げの内容)。

## 課題

1. 転記課題: 誤りをあらかじめ埋め込んだ原稿(音声または点字で提示)を Word に打ち込む。打ち間違いは自然に生じるため、そのまま観察する。
2. 校正課題: 誤りを埋め込んだ文書を開き、一定時間内に見つけて直す。埋め込む誤りはユーザー辞書に登録し、確実に検出されるようにする。
3. 自由作文課題: テーマを与えて短い文章を書く。生態学的妥当性の確認用。

各課題は 5 分から 10 分程度、条件ごとに異なる同難度の文書を用意する。

## 指標

客観指標(アドインのログから算出)

- 検出数、通知数、解消数、未解消数。
- 通知から修正までの時間(`timeToFixFromNotifyMs`)の平均と中央値。
- 検出から修正までの時間(`timeToFixFromDetectMs`)。
- 課題終了時に残った誤りの数(見落とし)。
- ナビゲーション操作の回数(「次の誤りへ」など)。

主観指標(質問紙)

- 作業負荷: NASA-TLX(日本語版)。
- 使いやすさ: SUS(システムユーザビリティスケール)。
- 独自項目(5 件法): 音で誤りに気づけた、音は作業の邪魔にならなかった、種別の違いが分かった、読み上げは十分だった、日常的に使いたい。
- 自由記述と半構造化インタビュー(音の好み、うるさく感じた場面、欲しい機能)。

## 手順

1. 説明と同意の取得。
2. 練習(5 分): 効果音の聞き分け練習(「テスト音」ボタン)、操作の練習。
3. 本試行: 条件ごとに課題を実施。開始前にログを消去し、参加者 ID と条件を入力して「監視を開始」。終了時に「CSV を保存」または「CSV をコピー」でログを保存する。
4. 条件ごとに質問紙。
5. すべて終了後にインタビュー。

所要時間は 60 分から 90 分を見込む。

## 分析

- 修正時間は対数変換のうえ、条件を要因とする反復測定分散分析または線形混合モデル。
- 見落とし数はポアソン回帰または一般化線形混合モデル。
- 質問紙はフリードマン検定などノンパラメトリック検定。
- 効果量と 95% 信頼区間を併記する。

## 倫理面の配慮

- 所属機関の研究倫理審査を受ける。
- 音の大きさは参加者ごとに事前に調整し、不快な場合は中断できることを伝える。
- ログには文書の誤り箇所の文字列が含まれるため、個人情報を含む文書は使わない。
- スクリーンリーダーの読み上げと効果音が重なる場合の負担を観察し、必要に応じて読み上げの内容を「種類のみ」にする。

## ログの形式

出来事のログ(CSV)の列

- t: エポックミリ秒
- iso: ISO 8601 の時刻
- participant: 参加者 ID
- condition: 条件
- kind: 出来事の種類(session_start, scan, error_detected, error_notified, error_deferred, error_resolved, navigate, replace, setting_changed, note)
- key: 誤りのキー(種別|文字列|出現順)
- type: 誤りの種別(spelling, grammar, style)
- text: 誤りの文字列
- paragraphIndex: 段落番号(0 始まり)
- detail: 補足

誤りごとの集計(perError CSV)の列

- participant, condition, key, type, text
- detectedAt, notifiedAt, resolvedAt: それぞれの時刻
- timeToFixFromNotifyMs: 通知から修正まで
- timeToFixFromDetectMs: 検出から修正まで

## 事前検証(パイロット)

- ブラウザ版デモ(`npm run demo`)で音の聞き分けを確認する。
- 2 名から 3 名で手順を通しで試し、課題の長さ、埋め込む誤りの数(目安 8 件から 12 件)、音量を調整する。
