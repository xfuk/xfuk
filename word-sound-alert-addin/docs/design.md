# 設計メモ

## 目的

Word で執筆中に生じたスペルミス・文法エラーを、視覚に頼らず気づけるようにする。
下線という視覚的な手掛かりを、効果音(イヤコン)と読み上げという聴覚的な手掛かりで補う。

## 全体の流れ

```mermaid
flowchart LR
  A[Word 文書] -->|段落テキストとカーソル位置| B[チェッカー]
  B -->|誤りの一覧| C[差分追跡 ErrorTracker]
  C -->|新規 / 解消| D[通知ポリシー NotificationPolicy]
  D -->|通知すべき誤り| E[イヤコン EarconPlayer]
  D --> F[読み上げ Speaker]
  D --> G[ライブリージョン]
  C --> H[注釈(下線) WordApi 1.7]
  C --> I[評価ログ EvaluationLog]
```

1. 段落ごとのテキストを取得し、改行で結合して 1 回の検査にかける(LanguageTool の呼び出し回数を抑えるため)。
2. 誤りの位置を段落番号と段落内位置に変換する。
3. 前回の一覧と比較し、新しく現れた誤りと解消した誤りを求める。キーは(種別、文字列、文書内での出現順)で、位置は使わない。誤りより前で文字を入力しても再通知されない。
4. 通知ポリシーが、入力中の語を保留し、多数同時の場合はまとめ通知にする。
5. 効果音、読み上げ、ライブリージョンの順に、重ならないよう直列に出力する。
6. 出来事をログに記録する。

## Office.js の制約と選択

Word の JavaScript API には、Word 標準のスペルチェック結果を取得する API がない。
選択肢と判断は次のとおり。

- VSTO / VBA (COM): `Range.SpellingErrors`、`Range.GrammaticalErrors` で Word 標準の結果が取れる。ただし Windows 専用で、配布と保守の負担が大きい。将来、Word 標準の判定と比較したい場合の対照実装として検討する価値がある。
- Office.js + 独自検査(本実装): クロスプラットフォームで配布が容易。検出精度は使うエンジンに依存する。
- Office.js の注釈 API (WordApi 1.7): 本文に独自の下線(批評注釈)を引ける。Word 標準の下線は読めないが、自分で引いた下線と音の対応は取れる。

## 検出エンジン

- BuiltinChecker: 正規表現ルールとユーザー辞書。辞書は「誤り,正しい語」の行形式。英語は単語単位、日本語は部分一致。評価実験で埋め込む誤りを確実に検出する用途に向く。
- LanguageToolChecker: `/v2/check` に text と language を POST し、`matches` を共通形式に変換する。`rule.issueType` が misspelling ならスペル、grammar などなら文法、それ以外は表記に分類する。
- CompositeChecker: 複数のエンジンを併用し、同一位置の重複を除く。片方が失敗しても残りの結果を返す。

## 通知の設計

イヤコンは短く(1 秒未満)、種別で区別がつくように音色と輪郭を変えている。

- スペル: 矩形波、880 Hz から 660 Hz へ下降する 2 音。
- 文法: 三角波、330 Hz の長めの 1 音。
- 表記: 正弦波、1320 Hz の短い 1 音(既定ではオフ)。
- 修正: 正弦波、660 Hz から 990 Hz へ上昇する 2 音(肯定的なフィードバック)。
- まとめ: 880 Hz の 3 連音。

プリセットは `src/core/sound.js` の `EARCON_PRESETS` にデータとして定義しているため、実験条件に応じて差し替えやすい。
「単一音」プリセットは種別を区別しない比較条件用である。

読み上げは日本語の種別ラベルと、語(英語なら英語音声)、必要なら 1 文字ずつの綴りの順に発話する。
ライブリージョンは `aria-live="assertive"` で、同じ文を続けて読ませるために一度空にしてから更新する。

## 入力中の扱い

カーソルが誤りの範囲内またはその直後にある間は「入力中」とみなして通知を保留する。
たとえば `teh` と打った直後は鳴らさず、空白や句読点を打った時点で鳴らす。
語の途中で鳴ると入力の妨げになるためで、この挙動は設定でオフにできる(比較条件として使える)。

## Word との橋渡し(src/taskpane/taskpane.js)

- 読み取り: `body.paragraphs` の `text` と `uniqueLocalId`(WordApi 1.6)、選択範囲の先頭段落と、段落先頭から選択末尾までの範囲の文字数(カーソルの段落内位置)。
- 変更の検知: `onParagraphChanged` / `onParagraphAdded` / `onParagraphDeleted`(WordApi 1.6)とポーリングの併用。イベント非対応の環境ではポーリングのみ。
- 移動: 段落内で誤りの文字列を `search` し、出現順で該当する範囲を `select` する。
- 置換: 同様に範囲を特定して `insertText(候補, 'Replace')`。
- 注釈: `paragraph.insertAnnotations` で批評注釈を挿入。誤りの集合が変わった段落だけ更新する。ポップアップで候補が選ばれたら `onAnnotationPopupAction` で置換する。非対応環境では自動的に無効化する。

## 今後の課題

- Word 標準の判定との一致率の測定(VSTO で `SpellingErrors` を取り出して比較)。
- 日本語の検出強化(形態素解析ベースの校正 API の追加、たとえば自前の LanguageTool サーバーや他の校正サービス)。
- 共有ランタイムを使ったキーボードショートカット(タスクペインにフォーカスがなくても操作できるようにする)。
- 音の定位や高さで「文書内のどこか」を表す手法の比較。
